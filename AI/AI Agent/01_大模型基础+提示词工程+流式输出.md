## 一、大模型原理
  ### 1.1 核心本质
  - (1)词嵌入：将文字转化为向量:将文字转化为token,为每个token生成包含语义的向量，模型通过计算向量的距离来理解语义的关联性
  - (2)注意力机制：生成内容的时候忽略无关词汇，能够准确判断句子中各成分的核心关联度。多个注意力头分别捕获语义，逻辑等不同维度的信息

  - 高质量数据准备与治理

---

  > 在预训练模型基础上，使用高质量数据集进行小范围参数调整，使模型学会理解并遵守指令

## 二、AI Agent
  ### 2.1 什么叫AI Agent
  > Agent = **LLM** (大脑) + **Planning** (规划) + **Tool use** (执行) + **Memory** (记忆)。
  - LLM (大脑)： 作为核心推理机，负责理解意图、生成文本和进行逻辑判断。
  - 规划Planning： 能够将复杂的目标（如"帮我策划一场技术沙龙"）拆解成可执行的步骤，最重要的是让LLM具备**子任务拆解**和**反思**能力，让它形成思维树和思维链。
  - 记忆Memory： 包括短期和长期两种。短期记忆：执行上下文。长期记忆一般指外部知识库。
  - 工具使用Tool Use： 能够根据需求去查谷歌搜索、读数据库、甚至跑 Python 代码。
---
  ### 2.2 AI Agent增强的方法
  > 普通的 LLM 只是 One-shot（一次性） 的响应，而 Agent 的核心在于 Iterative（迭代）。ReAct 模式 (Reason + Act) 是目前最主流的 Agent 推理逻辑，它通过**推理**和**行动**来增强推理和决策的效果
  - 1.Thought (思考)： 模型描述当前要做什么，为什么要这么做。
  - 2.Action (行动)： 模型选择一个工具（如：Google Search）。
  - 3.Observation (观察)： 模型读取工具返回的结果。
  - 4.Repeat (循环)： 重复上述步骤，直到得出最终答案。

## 三、prompt提示词工程
  ### 3.1 prompt组成
  - systemMessage：来自系统的消息，开发人员定义
  - userMessage:来自用户的消息
  - AiMessage：来自AI生成的消息，通常是对userMessage的响应
  - ToolExecutionResultMessage:这是ToolExecutionRequest的结果
  - CustomMessage：自定义消息，可以包含任意属性
---
  ### 3.2 prompt演化进程
  > 简单的纯字符串提问问题 --> 占位符 --> 多角色消息
---
  ### 3.3 提示词原则
  - **角色设定 (Role)**：给模型分配身份，“你是资深产品经理”
  - **任务指令**：清晰告诉要做什么，动词明确：总结、翻译、对比、生成方案、纠错
  - **背景 / 上下文**：提供必要输入例子或者材料，不要让模型猜
  - **输出要求**：格式（表格、markdown、列表、json）、长度、语气、受众、禁止输出内容
---
  ### 3.4 prompt的COT思想
  > ✅ CoT适合：数学计算、逻辑推理、阅读理解、复杂判断、方案分析、排除干扰条件的题目
  > ❌ CoT不适合：简单翻译、简短文案生成、简单摘要；用了只会多出一堆废话，不会提升质量。
  - (1)**Zero-shot学习**：**零样本学习**，在训练阶段不存在与测试阶段完全相同的类型，但是模型可以使用训练过的知识来推广到测试集中的新类别上
    ```js
      // ❌ 普通 Prompt：
      甲有 5 个苹果，乙比甲多 3 个，丙的苹果是乙的两倍，丙有多少个苹果？直接给出答案。
      // ✅ 零样本 CoT Prompt：
      甲有 5 个苹果，乙比甲多 3 个，丙的苹果是乙的两倍，丙有多少个苹果？请一步步思考，然后给出最终答案。
    ```
  - (2)**Few-shot学习**：少样本学习，当模型在学习了一定类别的大量数据后，对于新的类别只需要少量的样本就能快速学习。相当于有了一定的参考样本
    ```
      任务：判断下面句子是否符合现实常识。
      示例 1：
      输入：鱼生活在土壤里
      思考：鱼依靠水生存，土壤不是鱼的生存环境，这句话不符合常识。
      输出：不符合

      示例 2：
      输入：鸟可以在天空飞翔
      思考：鸟类拥有翅膀，多数鸟类能够在空中飞行，这句话符合常识。
      输出：符合

      现在处理新问题：
      输入：铁锅是用纸做的
      思考：
      输出：
    ```
  - (3)**Self‑Consistency 自一致性（CoT 增强）**
  > 让模型生成**多套不同的思考路径**，再汇总选出最合理答案.
  - (4)**ReAct 推理 + 行动**

  ### 3.5 python内置字典json转化库
  > json.dumps(字典或者列表，ensure_ascill = False):将python数据结构字典或者列表转化成Json字符串
  > json.loads(json字符串):将json字符串转化为python数据结构
  ```python
      import json
      d = {
        "name":'lisa'
      }
      print(json.dumps(d, ensure_ascii = False)) # {"name": "lisa"}
      json_str = '{"name":"lisa"}'
      print(json.loads(json_str)) # {'name': 'lisa'}
  ```

  ### 3.6 进阶
  - RAG场景下的提示词：检索增强生成，学会写 RAG 专用 prompt：把检索回来的参考文档喂给模型，约束模型只能基于参考资料回答，减少幻觉。
  - 多模态prompt：图片理解、文生图提示词逻辑：描述主体、风格、构图、光影、负面描述
  - 工具调用（Function Calling）提示：现在 LLM 应用主流：写提示词配合函数调用，让模型调用外部工具（搜索、数据库），不再只靠模型内部知识。
  - 微调 vs Prompt 工程边界：什么问题改 prompt 就能解决；什么问题 prompt 搞不定，需要微调模型，不要盲目写复杂超长 prompt。

  ### 3.7 prompt进阶技巧
  - (1)CoT,思维链:让AI生成更多相关的内容，构成更丰富的上文，从而提升下文的正确率
  - (2)自洽性，相当于验算
  - (3)TOT,思维树：树形展开搜索，判断输入内容更接近哪个叶子节点

## 四、Function Calling
  ### 4.1 组成
  **用户prompt**(原始需求输入)+**大模型LLM**(决策中心)+**Function**(工具函数)+**程序本地逻辑**
  - 程序本地逻辑：解析LLM输出的调用执行，调用对应Function并传入参数，真正执行函数逻辑
---
  ### 4.2 完整链路
  工具选择 --> 参数生成 -->  本地执行 --> 结果回传 --> 模型总结回答
---
  ### 4.3 Function Call的能力
  - 模型预训练的函数调用范式
  - 结构化输出能力
  - JSON格式约束能力
---
  ### 4.4 为什么普通Prompt无法替代标准Function Call
  - 格式稳定性差
    - 普通prompt的模型本质是自由文本生成，容易跑偏。
    - 原生Function call 
  - 意图识别差
  - 上下文与多轮调用能力弱
  - 工程落地成本高，不可控
---
  ### 4.5 核心定义
  - **name**:函数名称
  - **description**:函数整体描述
  - **parameters**:参数根对象
  - **properties**:参数名字集合
  - **required**:必选参数列表
---
  ### 4.6 单轮调用 VS 多轮调用
  > 单轮调用：大模型**只生成一次工具调用请求**，执行工具后，结果直接返回给用户，**不再二次触发工具**
  > 多轮Function Call:单次对话中**连续多次触发工具调用**，可能是同一个工具循环调用，或者多个不同的工具一次调用，场景比如：分页查询海量数据，生活综合任务（多工具组合）
---
  ### 4.7 复杂任务的自动拆解和链式调用
  - 强固定链式
  - 动态自适应链式
---
  ### 4.8 优化Function Call调用技巧
  ### 4.9 Function Call业务应用场景
  #### (1)智能问答增强：知识库检索+工具调用结合
  #### (2)实时信息获取：天气，新闻，汇率，数据查询
  - 思路
    - ·用户提问一大模型识别意图(查天气/新闻/汇率等)
    - ·模型自动选择并调用封装好的第三方API工具
    - ·工具发起HTTP请求获取实时数据，返回原始结果
    - ·大模型对原始数据做语义整理、润色、问答回复，输出自然语言答案
  - 适用落地场景
    - ·生活服务:实时天气、空气质量、限行、快递查询
    - ·金融数据:实时汇率、股价、基金净值、行情
    - ·资讯类:热点新闻、行业快讯、赛事结果
    - ·政务/业务:快递物流、手机号归属、IP地址查询等
  - 技术架构
    - 用户提问 一LLM意图识别+函数调用 一 自定义工具(HTTP请求对接第三方API)一数据回传LLM

## 五、流式输出（打字机效果）SSE
  ```python
    from openai import OpenAI
    from sympy import true

    client = OpenAI(
        base_url="https://ws-omu6172u8mjmo9ut.cn-beijing.maas.aliyuncs.com/compatible-mode/v1",
        api_key="sk-XXX",
    )
    stream = client.chat.completions.create(
            model="deepseek-v4-pro",
            messages= [{"role":"user", "content":"北京有什么好吃的"}],
        stream=True
    )
    full_text = ""
    for chunk in stream:
        # 部分chunk为空，要做判断
        if chunk.choices and chunk.choices[0].delta.content:
            text = chunk.choices[0].delta.content
            full_text += text
            print(text, end="", flush=True) # 实时打印，打字机效果
    print("\n\n完整结果：", full_text)
  ```
