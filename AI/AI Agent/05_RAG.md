## 一：RAG模型
  > RAG 核心流程：文档解析 → 分块 → 向量化 → 向量存储 → 检索 → 重排序 → 生成
  ### 1.1 核心原理
  - 第一步：数据预处理：搭建一个知识库，支撑后面的检索
    - 知识库构建：收集文档，网页搜索资源等外部数据，组成自己的数据库
    - 文档分块
    - 向量化处理：使用嵌入模型将文本块转化为向量，并存储在向量数据库中
    - 索引
  - 第二步：检索阶段：找到合适的参考文档，检索方式的选择
    - 查询处理
    - 重排序
  - 第三步：生成阶段：整合提问和参考文档，提示词构建，大模型的选择
    - 上下文组装：将搜索到的文本片段与用户的问题相结合，形成增强的上下文输入
    - 生成答案

  ### 1.2 实例步骤
  - 数据准备：文档分片-->建立索引-->建立Embedding模型-->生成向量-->向量数据库
  - 回答问题:向量数据库召回几个相关度最高的片段-->重排-->生成相关度最高的片段
  ### 1.3 Embedding模型
  > 将文本转换为数字，比如text-embeding-5
  ### 1.4 分块策略：
  - 第一层：基础分块(固定长度，递归字符，按句分块)
  - 第二层：结构感知(MarkDown,html),对话轮次
  - 第三层：语义/主题(向量相似度，LDA主题模型)
  - 第四层：高级策略(小-大分块，代理式分块)
    - 小-大分块：结合小块的高精度和大块生成的高上下文优势。用小分块进行检索，然后用它对应的大块父文档来回答问题。
    - 代理式分块：赋予LLM判断能力，让它能够根据问题动态识别文档所属知识单元。
  ### 1.5 检索优化
  - RAG-Fusion:基于RRF算法对多个查询结果进行打分重排
  ### 1.7 纯向量搜索的局限性：
  - 混合搜索：结合了BM25稀疏检索和向量检索稠密检索，通过langchain实现了代码展示了如何整合这两种检索方式。

## 嵌入：两个向量之间的距离用来描述他们的相关性
  - 搜索(查询出与某字符串相关的所有结果并排名)
  - 聚类(文本字符串按照分相似性进行分组)
  - 推荐(推荐具有相关文本字符串的项目)
  - 异常检测(识别出相似性很小的异常值)
  - 多样性测量(分析相似性分布)
  - 分类(文本字符串按照最相似的标签进行分类)

## LLM和RAG的区别
|      维度  |           LLM           |                       RAG                        |
|:---------:|:-----------------------:|:-------------------------------------------------:|
| 效率与成本  | 处理上下文时计算资源消耗大   |               RAG通过检索片段减少输入长度            |
| 知识更新    | 依赖上下文数据，无法更新数据 |                  连接知识库，增强时效性              |
|  可解释性   |       生成过程比较难追溯   |                检索来源透明，用户可查看来源           |
|    定制化  |        无法满足特定需求    |                可以对特定领域进行定制化检索系统        |
|  数据隐私  |           从云端检索      |   允许在本地私有化数据源上检索，避免了敏感数据上传到云端  |
