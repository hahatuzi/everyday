## 〇、总览：按场景选型

| 文件大小 | 上传做法 | 下载做法 |
|----------|----------|----------|
| < 100MB | 普通 `multipart` 整包传 | 普通流式响应 |
| 100MB ~ 2GB | **分片上传**（秒传 + 断点续传） | 流式 + `Range` 断点续传 |
| > 2GB 或 面向公网海量 | **对象存储直传**（OSS/S3 预签名） | **CDN / 对象存储直链** |
| 服务端动态生成的大文件（报表/导出） | — | **异步任务**：预生成 → 轮询 → 临时签名链接 |

---

## 一、核心原则

1. **文件不进业务后端就对了**：能走对象存储/CDN 的，别让应用服务器中转，这是大厂标准姿势
2. **必须走后端时，全程流式处理，严禁整包读进内存**
3. **前端解决"体验"**（进度 / 暂停 / 并发 / 秒传），**后端解决"可靠"**（落盘 / 合并 / 校验 / 续传状态）

一句话：大文件传输的痛点无非三个——**内存、超时、中断成本**。解法是 **分片 + 并发 + 秒传/断点 + 全链路流式**。

## 二、大文件上传 · 前端实现

### 2.1 接口约定

| 接口 | 作用 |
|------|------|
| `POST /upload/check` `{hash}` | 秒传检测：返回 `{needUpload, uploadedChunks:[]}` |
| `POST /upload/chunk` FormData | 上传单个分片（`hash, index, total, chunk`） |
| `POST /upload/merge` `{hash, filename}` | 全部传完通知后端合并 |

### 2.2 哈希计算（放 Web Worker，避免卡死页面）

```js
// src/utils/hashWorker.js
self.onmessage = async (e) => {
  const { file, chunkSize } = e.data;
  const spark = new SparkMD5.ArrayBuffer(); // npm i spark-md5
  const totalChunks = Math.ceil(file.size / chunkSize);
  for (let i = 0; i < totalChunks; i++) {
    const buf = await file.slice(i * chunkSize, (i + 1) * chunkSize).arrayBuffer();
    spark.append(buf);
    self.postMessage({ type: 'progress', percent: Math.round((i + 1) / totalChunks * 100) });
  }
  self.postMessage({ type: 'done', hash: spark.end() });
};
```

### 2.3 完整上传组件

```vue
<!-- Uploader.vue 大文件分片上传 -->
<template>
  <div class="uploader">
    <el-button type="primary" @click="chooseFile" :disabled="status !== 'idle'">
      {{ status === 'idle' ? '选择文件' : '上传中...' }}
    </el-button>
    <input ref="inputRef" type="file" hidden @change="onChange" />

    <div v-if="file" class="file-info">
      <p>{{ file.name }}（{{ formatSize(file.size) }}）</p>
      <el-progress :percentage="hashPercent" v-if="status === 'hashing'" text-inside />
      <template v-else>
        <el-progress :percentage="totalPercent" text-inside
          :status="status === 'done' ? 'success' : undefined" />
        <div class="ops">
          <el-button size="small" @click="toggle">{{ status === 'paused' ? '继续' : '暂停' }}</el-button>
          <el-button size="small" @click="reset">重新选择</el-button>
        </div>
      </template>
    </div>
  </div>
</template>

<script setup>
import { ref, reactive, computed } from 'vue';
import { ElMessage } from 'element-plus';
import axios from 'axios';
import SparkMD5 from 'spark-md5';

const CHUNK_SIZE = 2 * 1024 * 1024; // 2MB/片
const MAX_CONCURRENT = 3;           // 并发片数

const inputRef = ref(null);
const file = ref(null);
const status = ref('idle'); // idle | hashing | uploading | paused | done
const hashPercent = ref(0);

const hash = ref('');
const chunks = reactive([]);   // 每个分片的状态
const uploadedCount = computed(() => chunks.filter(c => c.done).length);
const totalPercent = computed(() =>
  !chunks.length ? 0 : Math.round(uploadedCount.value / chunks.length * 100));

const chooseFile = () => inputRef.value.click();
const onChange = (e) => {
  const f = e.target.files[0];
  if (!f) return;
  if (f.size > 50 * 1024 * 1024 * 1024) return ElMessage.warning('超过 50G，暂不支持');
  reset();
  file.value = f;
  run();
};

function reset() {
  file.value = null; hash.value = ''; chunks.length = 0;
  hashPercent.value = 0; status.value = 'idle';
}

async function run() {
  status.value = 'hashing';
  hash.value = await computeHash(file.value); // 正式环境换 hashWorker.js
  hashPercent.value = 100;

  // 1) 秒传 + 断点续传检测
  const { data } = await axios.post('/upload/check', { hash: hash.value });
  if (data.needUpload === false) return done();               // 秒传：文件已存在

  const total = Math.ceil(file.value.size / CHUNK_SIZE);
  const uploadedSet = new Set(data.uploadedChunks ?? []);     // 已传过的片
  for (let i = 0; i < total; i++) {
    chunks.push({
      index: i,
      done: uploadedSet.has(i),
      retry: 0,
      aborted: false,
      percent: uploadedSet.has(i) ? 100 : 0,
    });
  }

  status.value = 'uploading';
  await uploadAll();
  if (status.value !== 'paused') {                            // 2) 全部完成 → 合并
    await axios.post('/upload/merge', { hash: hash.value, filename: file.value.name });
    done();
  }
}

const done = () => { status.value = 'done'; ElMessage.success('上传成功'); };

// ---- 分片并发上传（带失败重试 + 暂停恢复）----
let controller = null;
async function uploadAll() {
  controller = new AbortController();
  const pending = chunks.filter(c => !c.done);
  let cursor = 0;

  const worker = async () => {
    while (cursor < pending.length && status.value !== 'paused') {
      const item = pending[cursor++];
      await uploadChunk(item, 0);
    }
  };
  const pool = Array.from({ length: MAX_CONCURRENT }, worker);
  try { await Promise.all(pool); } catch (_) { /* 单个片失败已内部处理 */ }
}

async function uploadChunk(item, retry) {
  const slice = file.value.slice(item.index * CHUNK_SIZE,
                                Math.min((item.index + 1) * CHUNK_SIZE, file.value.size));
  const fd = new FormData();
  fd.append('hash', hash.value);
  fd.append('index', item.index);
  fd.append('total', chunks.length);
  fd.append('chunk', slice, file.value.name);

  try {
    await axios.post('/upload/chunk', fd, { signal: controller?.signal });
    item.done = true;
  } catch (err) {
    if (axios.isCancel(err)) return;              // 暂停：正常中断
    if (retry < 3) {                              // 3) 失败重试，退避 1s/2s/4s
      await new Promise(r => setTimeout(r, 1000 * 2 ** retry));
      return uploadChunk(item, retry + 1);
    }
    status.value = 'error';
    ElMessage.error(`分片 ${item.index} 上传失败`);
    throw err;
  }
}

function toggle() {
  if (status.value === 'uploading') { status.value = 'paused'; controller?.abort(); }
  else if (status.value === 'paused') { status.value = 'uploading'; uploadAll(); }
}

// ---- 辅助 ----
async function computeHash(f) {
  // 演示：主线程版。真实项目用上方 hashWorker.js 避免卡 UI
  const spark = new SparkMD5.ArrayBuffer();
  const total = Math.ceil(f.size / CHUNK_SIZE);
  for (let i = 0; i < total; i++) {
    spark.append(await f.slice(i * CHUNK_SIZE, (i + 1) * CHUNK_SIZE).arrayBuffer());
    hashPercent.value = Math.round((i + 1) / total * 100);
  }
  return spark.end();
}
const formatSize = (b) => b < 1024 ? b + 'B'
  : b < 1048576 ? (b / 1024).toFixed(1) + 'KB'
  : b < 1073741824 ? (b / 1048576).toFixed(1) + 'MB'
  : (b / 1073741824).toFixed(2) + 'GB';
</script>
```

### 2.4 上传的工程要点（面试常问）

1. **进度条不用 `onUploadProgress` 聚合**，而用「已成功分片数 / 总片数」——分片是并发小请求，单片进度聚合误差大且难算
2. **秒传 = 整个文件 hash 比对**；**断点续传 = 后端返回 `uploadedChunks`**，前端只补传缺失片（续传天然免费）
3. hash 用增量分片读算，1GB 文件在主线程会卡死，**必须上 Worker**
4. 暂停用 `AbortController`，注意区分「分片请求被取消」与「上传错误重试」

## 三、大文件上传 · 前后端协议与后端实现

### 3.1 阶段 1：文件哈希（前端算，后端登记）

```
前端: file → 分块增量算 MD5/SHA-1 → 得到 fileHash
前端: POST /upload/init { fileHash, fileName, size, chunkCount }
后端: 查表返回 {
         skipUpload: true,          // 秒传命中
         uploadedChunks: [0,1,2],   // 已有哪些片（断点续传用）
         uploadId: "uuid"           // 服务端本次上传会话
       }
```

要点：**hash 必须前端算**（文件没离开用户设备），**秒传/续传状态必须后端记**（Redis，key = `upload:{fileHash}`）。

### 3.2 阶段 2：分片上传

```
前端: 并发 3~5 个 POST /upload/chunk
      FormData: { uploadId, chunkIndex, chunkCount, chunk: Blob }
后端(Node/multer): multer diskStorage 直接流式写临时目录
      → /tmp/uploads/{uploadId}/{chunkIndex}.part
      → 每收完一片，Redis 记 uploadedChunks
前端: 全片完成 → POST /upload/complete { uploadId }
后端: 校验片数齐全 → 按序流式合并 → 校验总大小 → 清理临时文件
```

### 3.3 阶段 3：后端合并（不要整包读内存）

```js
// 合并所有分片（Node）
const { createWriteStream, createReadStream } = require('fs');
const { pipeline } = require('stream/promises');
const { Readable } = require('stream');

async function mergeChunks(uploadId, chunkCount, destPath) {
  await pipeline(
    // 用 Readable.from 依次流式串联所有 .part 文件，内存占用恒定
    Readable.from(
      (async function* () {
        for (let i = 0; i < chunkCount; i++) {
          const part = `${tmpDir}/${uploadId}/${i}.part`;
          yield createReadStream(part);
        }
      })()
    ),
    createWriteStream(destPath)
  );
}
```

### 3.4 Node 接收分片的正确姿势

**关键：用 `multer` 的 `diskStorage`（或 busboy），绝不能让它把文件 buffer 进内存。**

```js
const multer = require('multer');
const upload = multer({
  storage: multer.diskStorage({
    destination: (req, file, cb) => cb(null, `${TMP}/${req.body.uploadId}`),
    filename: (req, file, cb) => cb(null, `${req.body.chunkIndex}.part`),
  }),
  limits: { fileSize: CHUNK_SIZE + 1024 }, // 单片上限，防恶意
});

router.post('/upload/chunk', upload.single('chunk'), (req, res) => {
  redis.sadd(`upload:${req.body.uploadId}:done`, req.body.chunkIndex);
  res.json({ ok: true });
});
```

## 四、大文件下载 · 前端实现

### 4.1 方案 A（推荐，展示进度）：XHR 拿真实下载进度

```js
// src/utils/download.js
/**
 * 带进度的大文件下载
 * @param {string} url 后端需返回 Content-Length
 * @param {object} opts { filename, onProgress }
 */
export function downloadWithProgress(url, { filename, onProgress } = {}) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('GET', url, true);
    xhr.responseType = 'blob';

    // 下载进度：需服务端给 Content-Length，且不要开 gzip 压缩（会失真）
    xhr.onprogress = (e) => {
      if (!e.lengthComputable) return;
      onProgress?.(Math.round((e.loaded / e.total) * 100), e.loaded, e.total);
    };

    xhr.onload = () => {
      if (xhr.status === 200 || xhr.status === 206) {
        const blob = xhr.response;
        const link = document.createElement('a');
        link.href = URL.createObjectURL(blob);
        link.download = filename;
        link.click();
        URL.revokeObjectURL(link.href); // 释放内存
        onProgress?.(100);
        resolve();
      } else reject(new Error(`下载失败: ${xhr.status}`));
    };
    xhr.onerror = () => reject(new Error('网络异常'));
    xhr.send();
  });
}
```

### 4.3 方案 C（真正流式写盘，仅 Chrome）：File System Access API

```js
async function streamDownload(url, filename) {
  const res = await fetch(url);
  const total = +res.headers.get('Content-Length') || 0;
  const handle = await showSaveFilePicker({ suggestedName: filename });
  const writable = await handle.createWritable();

  const reader = res.body.getReader();
  let loaded = 0;
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    loaded += value.byteLength;
    await writable.write(value);          // 每块立即写盘，不累积
    onProgress(Math.round(loaded / total * 100));
  }
  await writable.close();
}
```

### 5.2 支持 Range（断点续传的关键）

**HTTP 的 `Range` 头是最被低估的机制**——下载中断后可只请求剩余部分，浏览器原生下载器/迅雷也自动利用它，所以后端支持 Range 收益最大。

```js
router.get('/download/:id', async (req, res) => {
  const stat = await fs.stat(fullPath);
  const total = stat.size;
  const range = req.headers.range;               // 如 "bytes=1024-2047"

  if (range) {
    const [, startStr, endStr] = range.match(/bytes=(\d*)-(\d*)/) || [];
    const start = parseInt(startStr) || 0;
    const end = endStr ? Math.min(parseInt(endStr), total - 1) : total - 1;

    res.status(206);                              // Partial Content
    res.setHeader('Content-Range', `bytes ${start}-${end}/${total}`);
    res.setHeader('Content-Length', end - start + 1);
    pipeline(createReadStream(fullPath, { start, end }), res);
  } else {
    res.status(200);
    pipeline(createReadStream(fullPath), res);
  }
});
```

### 5.3 大文件导出的标准范式

服务端生成的大文件（导出报表、打包资源）**不要做实时流式下载**,它的坑和普通文件下载不一样：难点在于「生成」和「下载」是两件事，而且生成常常要几十秒到几分钟，直接流式响应很容易被网关超时切断。先分清阶段，再选方案。标准做法：

#### (1) 流程简述
> 动态报表下载的标准范式是 「提交任务 → 进度可见 → 取件下载」： 生成阶段异步化（不阻塞、不超时），进度用轮询/SSE 反馈，下载阶段用带签名的临时 URL 直链，大文件交给浏览器、不进前端内存。 再补上过期清理、按钮防重、失败可重试三个工程细节，就是生产级方案。
```
① POST /export/tasks            → 提交导出任务，后端返回 taskId
② 后端跑 SQL / 聚合 / 拼 Excel 异步生成文件到临时存储 →  耗时不可控，可能几分钟
③ 前端 GET /export/tasks/{id}   → 轮询 status: pending | done | fail
④ done 后返回一个带过期时间的下载 URL（如 5 分钟有效）
⑤ 前端拿到 URL 再触发下载
```
#### (2) 具体方案及对比
| 报表生成耗时 | 方案 | 适用 |
|----------|----------|----------|
| < 5 秒（几千行） | 实时流式响应，前端 blob 下载 | 小报表 |
| 5 秒 ~ 几分钟（几万~几十万行） | 异步任务 + 轮询/SSE 进度 + 临时签名 URL ← 标准做法 | 大多数导出 |
| 超大文件 / 高频访问 |生成后直传对象存储，返回 CDN 签名 URL | 大数据平台 |
要点：**下载链接要签名 + 过期**（防止扫 URL 白嫖），文件定期清理。
#### (3) 后端约定接口
| 接口 | 说明 |
|------|------|
| POST /api/export/tasks {reportType, params}  | 提交导出任务，返回 {taskId} |
| GET /api/export/tasks/:id | 	查询状态：{status, progress, filename, downloadUrl, expiresAt} |
| GET /api/export/tasks/:id/events | （可选）SSE 推送进度，替代轮询 |
| DELETE /api/export/tasks/:id | 取消任务 |
#### (4) 前端：任务封装（composable）
```js
// src/composables/useExportTask.js
import { ref, onUnmounted } from 'vue';
import axios from 'axios';

export function useExportTask() {
  const status = ref('idle');      // idle | pending | running | done | failed
  const progress = ref(0);         // 生成进度 0-100
  const taskId = ref('');
  const result = ref(null);        // { filename, downloadUrl, fileSize, expiresAt }
  const error = ref('');
  let timer = null;
  let stopped = false;

  const isBusy = () => ['pending', 'running'].includes(status.value);

  async function submit(payload) {
    reset();
    status.value = 'pending';
    try {
      const { data } = await axios.post('/api/export/tasks', payload);
      taskId.value = data.taskId;
      poll();                                   // 提交成功开始轮询
    } catch (e) {
      fail(e);
    }
  }

  function poll() {
    if (stopped) return;
    clearTimeout(timer);
    timer = setTimeout(async () => {
      try {
        const { data } = await axios.get(`/api/export/tasks/${taskId.value}`);
        status.value = data.status;
        progress.value = data.progress ?? 0;
        if (data.status === 'done') {
          result.value = data;
          return;                               // 结束轮询
        }
        if (data.status === 'failed') return fail(data.error);
        if (data.status === 'canceled') { status.value = 'idle'; return; }
        poll();                                 // 继续轮询
      } catch (e) {
        fail(e);                                // 网络错误也走失败
      }
    }, 1000);                                   // 1s 一次，可做退避
  }

  async function cancel() {
    if (!isBusy()) return;
    try { await axios.delete(`/api/export/tasks/${taskId.value}`); } catch (_) {}
    status.value = 'idle';
    progress.value = 0;
  }

  function fail(e) {
    status.value = 'failed';
    error.value = e?.response?.data?.message || e?.message || '导出失败';
  }

  function reset() {
    clearTimeout(timer);
    status.value = 'idle'; progress.value = 0;
    taskId.value = ''; result.value = null; error.value = '';
  }

  onUnmounted(() => { stopped = true; clearTimeout(timer); });

  return { status, progress, result, error, submit, cancel, reset };
}

```

> 轮询 1 秒一次，几百人同时导出会给后端带来无意义的查询压力。改用 SSE 推送，进度更实时：

```js
// 方案 A：Cookie 鉴权（最简单）

  progress.value = data.progress;
  if (data.status === 'done') { es.close(); /* ... */ }
};

// 方案 B：需要 Bearer Token 时，用 fetch + ReadableStream 手写 SSE 解析（可带 header）
async function listenSSE(url, token, onEvent) {
  const res = await fetch(url, { headers: { Authorization: `Bearer ${token}` } });
  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buf = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buf += decoder.decode(value, { stream: true });
    const lines = buf.split('\n\n');       // SSE 以空行分隔事件
    buf = lines.pop();
    for (const line of lines) {
      if (line.startsWith('data:')) onEvent(JSON.parse(line.slice(5).trim()));
    }
  }
}
```

## 六、网络层：最容易翻车的配置

| 层 | 配置 | 说明 |
|----|------|------|
| nginx | `client_max_body_size 0;`（关限制）或调大 | 不关的话超过 1m 直接 413 |
| 反向代理 | 关闭对大文件的缓冲 `proxy_buffering off;` | 否则代理层缓存整份文件，内存爆炸 |
| 网关/应用 | body 解析器 limit 调大或按路由跳过 | `express.json({limit})` 只对 JSON 生效 |
| 超时 | 上传路由、代理层超时调大 | 大文件传输常超 60s 默认值 |
| 压缩 | 大文件下载路径关闭 gzip | 否则 `Content-Length` 失真，前端算不出进度 |
| CDN | 直传场景配 CORS + 预签名 | 对象存储直传必须后端签临时凭证 |

## 七、对象存储直传（大型/公网文件标准答案）

```
① 前端要传文件 → POST /api/oss/upload-token { fileName, size }
② 后端鉴权后，向 OSS 申请预签名 URL / STS 临时凭证 → 返回给前端
③ 前端直接 PUT/POST 到 OSS（不经过业务后端，带宽压力全在 OSS）
④ OSS 回调 / 前端确认后 → POST /api/oss/complete 通知后端登记文件元信息
```

好处：业务后端零带宽压力、天然支持并发与断点、CDN 加速。

## 八、选型建议与面试速记

### 8.1 最小可跑的传输栈

| 角色 | 选型 |
|------|------|
| 文件尺寸 < 100MB | 整包 `multipart`，`multer.diskStorage` + 流式下载 |
| 100MB~2GB | 前端分片（2~5MB/片，并发 3）+ 后端 multer 收片合并 + Redis 记进度 |
| 文件最终在公网被大量访问 | 对象存储/CDN，绝不放应用服务器本地盘 |
| 必须自建后端 | 分片上传协议可参考 **tus**（开放标准，npm `tus-node-server`），别自己发明 |

### 8.2 面试速记

> 大文件传输的痛点无非三个——**内存、超时、中断成本**。
> 解法是 **分片 + 并发 + 秒传/断点 + 全链路流式**；
> 能把「何时走后端、何时直传对象存储」讲清楚，就比只会调库的人高一个段位。

### 8.3 后端必须配合的清单（自检）

1. `Content-Length` 必须真实返回，否则前端算不出进度
2. 大导出/下载接口必须流式响应（`res.pipe(createReadStream)`），否则后端先 OOM
3. 下载接口带 `Content-Disposition: attachment; filename*=UTF-8''xxx`
4. 上传合并时校验分片数、大小，防止前端被篡改
5. 分片上传状态用 Redis 存，支持服务重启后继续续传
